# KindleSpouse

Windows 桌面书库、找书试读与 Kindle 无线笔记管理。界面采用封面书库、收起的传输浮窗和直接嵌入页面的虚拟 Kindle。

**首次公开版：Windows v0.3.0。** [下载安装包](https://github.com/S1jinCheng/KindleSpouse/releases/latest) · [普通用户准备与安装步骤](docs/GETTING_STARTED.zh-CN.md)。增强模式已在 Kindle Scribe 一代实测；其他型号请先核对向导中的兼容条件。安装包尚未签名。

个人数据处理见 [PRIVACY.md](PRIVACY.md)，安全报告见 [SECURITY.md](SECURITY.md)，二进制分发与第三方源码对应关系见 [SOURCE_CODE.md](SOURCE_CODE.md)。参与开发后可运行 `npm run hooks:install` 启用当前仓库的推送前隐私检查。

## 从下载安装到两端连通

Windows 桌面端和定制 KOReader 插件由同一个仓库维护，统一安装入口在桌面应用的「设置 → 我的 Kindle → 选择设备与使用方式」。正式发布时使用 `KindleSpouse-版本-Windows-Setup.exe` 安装版；用户不需要下载源码、安装 Node、Go 或 Python。试读、书源登录和网盘授权均在应用内按提示完成，书源账号由用户自己登录。

原生模式无需越狱：选择型号、配置 Send to Kindle 邮箱并测试，随后可试读再发送。支持官方 Connections 的型号也可以选择网盘手动导入；原生模式不会自动收取 KOReader 同步目录，不提供真实 KOReader 阅读统计、自动笔记写回或定制休眠封面。

增强模式的向导分为四步：

1. 设备已经完成兼容的越狱，并安装 KOReader **v2026.07.1**。向导提供官方安装说明和适用于已有 KPM 的安装步骤；KPM 的当前版本可能不同，必须核对版本。向导不会修改固件、自动越狱或推断任意型号都兼容。
2. 保存并退出设备 KOReader，再用 USB 接到电脑。向导检查基础阅读器版本与已有配对。
3. 选择 Google Drive 或 OneDrive。首次安装额外为设备授权同一账号，随后自动安装定制首页、中文字体、同步程序及休眠封面，逐文件回读校验。更新已配对设备时保留授权、阅读设置、书籍、笔记和暂停状态；不会覆盖其他电脑的配对。安装中断可接回同一设备重试。
4. 收到校验完成提示后拔线，连接 Wi-Fi，打开 KOReader 并保持唤醒。向导等待本次组件版本及安装标识对应的真实网盘回执，收到后才开放「完成设置」。若设备原先处于暂停状态，需选择一次 Resume sync。回执只证明两端可以通信，整库笔记可能仍在后台传输；每本书仍以其收书回执判断送达。

完成后，电脑把确认下载的文件上传到专用 `KindleSpouse/Inbox`，Kindle 联网且 KOReader 运行时自动补收缺少的图书；笔记、标注和真实阅读记录从设备按变化上传到 `KindleSpouse/Sync`，电脑读取并验证。设备休眠、Wi-Fi 关闭或网络不可用时需等待恢复，电脑不会远程唤醒 Kindle。日常收书与笔记同步不依赖 USB；安装或更新组件需要一次接线。头像与封面设置保留局域网优先、网盘回退。

当前自动安装包包含 ARMv7 同步程序，实际设备验证基于第一代 Kindle Scribe；更早的硬件、不同固件和其他型号需分别验证。电脑要运行与设备相同的 KOReader 排版还需要 WSL Ubuntu；普通 EPUB/PDF 浏览器试读不要求 WSL。Calibre 作为可选的格式转换工具另行安装。

仓库中的 `native/companion/plugin` 是定制首页和同步插件，`native/companion` 是同步进程，`native/reader` 是电脑预览桥接；上游 KOReader 核心固定版本复用，尚未在这里维护完整核心分叉。桌面 MIT 与设备插件及第三方组件各自的许可证保持独立。`npm run package:device` 生成不带账号的公共组件包，首次设备授权只在本地生成；私有配对包、安装缓存、书籍、笔记和照片不得加入源码或公开附件。

开发者构建 Windows 安装版前依次准备桌面工具、KOReader 预览组件、设备工具和休眠封面：`npm ci`、`npm run tools:install`、`npm run tools:reader`、`npm run tools:companion`、`npm run tools:sleep-cover`，再运行 `npm run package`。设备工具构建需要 Go；电脑阅读器准备脚本需要 WSL Ubuntu。构建会校验字体、第三方许可、隐私规则与必需组件。`node scripts/verify-distribution.mjs release/win-unpacked/resources/native` 可检查安装包展开后的组件完整性。

`npm run test:distribution -- release/win-unpacked` 会启动真正打包后的 Windows 应用，使用独立的合成资料目录验证首次向导、EPUB 试读和生成的 NBK 笔记转 PDF，不读取真实用户书库或网盘授权。发布前还需验证实际安装器、Kindle USB 安装与首次联网回执；自动测试通过不等于所有型号均已实测。

## v0.3

- 书库支持封面／列表、搜索、排序、自建书集、批量整理、不同文件版本选择，以及从私有备份重建索引。MOBI、AZW、FB2、DOCX、TXT 等受支持原件可直接使用 KOReader 阅读；KFX/AZW3 等当前引擎未注册的格式保留归档，可转换的无 DRM 格式可由 Calibre 生成独立浏览器预览副本。
- 找书页直接显示豆瓣书目、作者、版本和页面提供的评分，并逐步显示本机、网盘传书目录和已登录书源的文件结果。网盘查询不会阻塞豆瓣书目；“查找版本”用于查找可下载的 KOReader 支持文件，豆瓣书目本身不会被当作下载文件。“豆瓣详情”在右侧隔离的应用内网页区域打开对应书籍，返回时保留搜索结果；需要登录或验证时由本人在页面完成。下载后可直接试读，确认后上传到网盘。
- 标注页为书籍、标注、常显阅读器三列。匹配唯一的原书版本后，根据正文引文定位并高亮；重复引文、版本不符、扫描 PDF 没有文字层时明确提示，不跳到猜测位置。
- 手写笔记依据容器页面结构及来源身份分类，区分独立笔记、书籍附属手写、其他资料和待识别格式。设备标题从只读内容目录关联，手动命名优先保留。缩略图使用设备原图，转换后的 PDF 支持翻页、跳页和导出。
- Google Drive／OneDrive 支持目录浏览、新建文件夹、上传、下载、移动、重命名和移入可找回的应用回收站。文本、Markdown、JSON、CSV 可编辑，保存前校验版本并保留旧内容；专用同步目录由应用管理。
- 左下角个人资料浮窗包含昵称、Kindle 今日阅读、统计日历、设置、设备和网盘入口。最近 52 周日历、累计时长和书籍列表仅统计 Kindle 上 KOReader 的真实阅读会话，经网盘同步更新。电脑试读不计入设备时长，旧电脑记录保留归档并排除统计；原生 Kindle 阅读器的时长尚未接入。
- 个人资料支持照片头像、昵称、个人简介和所在地；没有照片时使用文字头像与配色。可上传 8 MB 以内的 JPG、PNG、WebP，调整缩放与位置后保存为 256×256 PNG，取消编辑不会改动已有资料。头像立即显示在侧栏、资料菜单与个人页面。

## 个人头像与休眠封面

资料保存后自动在后台上传小型设置和按内容指纹保存的头像，不触发整库笔记同步。同一照片只上传一次。界面区分本机保存、上传中、网盘已保存和设备已接收；网络失败保留本机资料，可重试，重启应用也会补传尚未发布的设置。设备收到头像后校验指纹与 PNG 尺寸，成功后才替换现有资料并返回回执。简介和所在地仅保存在电脑，不随封面设置发送。

设备在配对校验后优先接收头像与封面设置，再处理标题、收书和笔记备份。新资料到达后，KOReader 会在后台同步仍进行时应用并预热图片，无需等整轮备份结束。书籍收取或后续备份失败不会撤回已接收的头像；首次同步尚未建立设备目录时仍可正常收书。

休眠封面自动使用 Kindle 当前阅读的书，不需要选择一张固定图片上传。KOReader 在书籍就绪和资料变更后准备适合屏幕尺寸的灰度书籍封面及圆形头像；休眠时复用这些图片，根据本机最新记录绘制阅读进度、今日时长和连续阅读天数，全程不依赖联网。书籍、头像或屏幕尺寸变化时更新对应缓存。它不是电脑提前生成的整张静态屏保，因此离线继续阅读后不会停留在上次网盘同步的数据。

设置页提供开关、小型预览和样式预览窗口。示例书籍选择收在窗口内，只影响电脑预览。电脑使用独立 KOReader 进程，沿用最近同步的阅读排版及统计；预览按书籍、位置、资料、统计和模板保存缓存，再次打开时复用，不切换当前正在阅读的进程。首次生成或内容变化时才重新渲染。

照片头像及图片预热需要新版设备组件。已有授权无需重做，但旧组件需要退出 KOReader 后通过 USB 更新一次；此后资料与笔记仍走网盘。电脑 KOReader 渲染、隔离网盘收发和设备回执可自动验证，实际 Kindle 安装及休眠显示仍需设备操作确认。

## 中文书库与找书界面

两页以 Noto Serif SC 宋体呈现标题和书名，菜单与操作采用 Noto Sans SC 黑体。暖白主画布搭配浅灰褐侧栏，以封面、书名和作者组织信息，橙褐色用于主要搜索操作与链接。书库提供继续阅读、封面／列表切换和中文搜索；存储位置及不同版本收在书籍的整理菜单。找书页保留左侧原生 KOReader 预览，右侧显示搜索结果、豆瓣书评和可下载版本，书源账号状态可展开查看。界面字体和样式只影响应用外壳，不改动 KOReader 的正文、字体或分页。

书库支持格式、作者及来源交叉筛选，可叠加书名搜索、正在读／已读、文章与自建书集。筛选先作用于文件版本，再合并同一本书，避免选中 EPUB 后打开该书的 KFX 版本。合作作者可分别筛选，缺失的作者信息归为“未提供作者”；切换页面或重新打开应用会保留筛选，一键清除可恢复全部书籍。更改筛选会清空批量选择，避免整理当前不可见的文件。

找书页的传输记录、导入与传书集中在同一行，传书方式及网盘账号在确认窗口中选择，默认网盘。侧栏保留导航和个人资料入口，连接详情在网盘页查看。

豆瓣书籍、搜索及书评页面以阅读模式嵌入右栏，沿用应用暖白背景、本地宋体标题及黑体正文，内容适应右栏宽度。站点导航、广告、推荐侧栏收起，书评原作者、评分、正文、展开／收起与站内链接保留。顶部显示当前网页标题及豆瓣来源，可切换原网页或在浏览器打开当前地址；返回搜索保留原来的查询与结果。登录、验证或尚未识别的网页保持原样，不套用阅读样式。适配依赖已识别的网页结构，上游改版时可使用原网页。

`npm run dev` 和 `npm run build` 会先校验字体。首次构建从 Google Fonts 的固定源码版本获取约 24 MiB 的原始可变字体和 OFL 许可，缓存到忽略提交的 `public/fonts`；后续构建直接复用校验通过的本地文件。字体及许可均校验固定 SHA-256，并随应用打包，不向源码仓库提交字体二进制。

## Zlib 登录与下载

在“找书与试读”点击“登录书源”，在独立的书源窗口完成网页登录。应用只接收上游支持域名上的账号会话，不接触或保存登录密码；会话使用当前 Windows 用户的系统加密存储。先调用账号接口验证，再显示“Zlib 已连接”和当天剩余下载次数。登录失效、网页验证、额度用尽和网络中断分别显示提示；“验证登录”可手动刷新账号状态。

登录验证成功后，已经输入的搜索会自动刷新。搜索结果区分书目与可下载文件，书源版本显示作者、语言、文件格式、大小、出版方和年份。豆瓣、Zlib 和网盘分别返回结果，慢网盘查询不会拖住已返回的 Zlib 文件。每个文件结果右侧先显示“试读”，由固定版本 `heartleo/zlib v0.0.8` 或对应网盘取得指定版本，完整性检查通过后进入虚拟 Kindle。真正打开成功后，同一版本的按钮变为“下载”；点击即确认将已试读的同一份文件上传到默认网盘，回读校验后发布 Kindle 领取清单，不再弹二次确认。重复搜索复用按来源编号、版本及内容指纹关联的缓存，其他版本仍需单独试读。字节数与检查状态保留在右上角传输记录。

下载到网盘的主要入口只保留在书籍结果行，顶部保留导入与传输记录。书籍信息的“更多操作”保留“保存原文件到电脑”和其他传书方式；保存到电脑前后均校验内容指纹。书籍信息中的“查找完整下载版本”按书名和已知作者搜索书源及网盘，并切到“可下载”列表。豆瓣详情顶部“查找下载”使用当前书目标题返回应用找版本。豆瓣网页不作为电子书文件，临时账号链接或凭证不会暴露到界面。

试读本身不产生上传任务，结果行的“下载”点击就是本次传书确认。按钮显示下载中、校验中、待同步、已在 Kindle 或重试下载；只有取得已配对设备、相同账号及相同内容指纹的实际落盘回执后才显示已在 Kindle。电脑每 15 秒轻量检查待收书任务的回执，不为此下载笔记快照。下载中断、格式无效、零字节、多文件结果或超过 200 MB 时不会进入试读区。未连接默认网盘时引导连接，失败任务保留并重试，不重复向书源下载。

## 文件格式

下载、文件选择、拖入、书库、网盘查找、原生试读、OPDS 与设备领取使用同一份格式注册表，与随应用安装的 KOReader v2026.07.1 文档提供器对齐，共 60 个后缀，不包含可执行脚本。支持 MOBI/AZW/PRC/PDB、EPUB/EPUB3、PDF、FB2/FB3、TXT/Markdown、HTML/HTMLZ、RTF、DOC/DOCX/DOCM/ODT、DJVU、CHM、XPS、漫画及图片等，也识别 FB2.ZIP、TXT.ZIP 等组合后缀和大写扩展名。完整列表见 `src/book-formats.json`；新增格式须同步生成并校验设备端列表。

原生试读直接打开下载的原件，不预先转换为 EPUB；明确确认后的传书同样保留原件字节。浏览器近似模式仅用于 EPUB/EPUB3/PDF，其他受支持文档自动使用 KOReader。文件须通过类型、完整性与大小检查，平台 DRM 文件不可试读或发送。支持某种格式不保证上游引擎能解析每份文档；例如个别 DOCX 会触发原生解析失败，应用保留原件并提示更换版本。

已配对的旧版 Kindle 组件仅接收 EPUB/PDF。发送其他格式前，需安装一次新版设备组件，再经 Wi-Fi 运行同步并在电脑读取回执，确认格式能力版本。桌面会拦截发往旧组件的新格式任务，避免阻塞已有传书队列。组件安装完成后，日常书籍领取、笔记与标注仍只走网盘。

设备笔记与书库按来源目录分开：`.notebooks` 内的笔记原件、缩略图、模板和缓存不进入书库，`.sdr` 附属文件与 `My Clippings.txt` 也不作为图书导入。真实笔记继续在「笔记与标注」显示其已匹配或手动设置的标题；缩略图只作笔记资源使用。旧版误入库的记录在读取时排除，原始快照、记录和阅读资料保持保留。此规则同时应用于 USB 导入、网盘快照恢复、Calibre 元数据入口、本机搜索、OPDS 与试读；独立图片书籍仍正常支持，不根据 PNG 格式或 UUID 文件名一概排除。

## KOReader 原生预览

电脑试读默认使用独立的 KOReader v2026.07.1，与当前设备同版，并按 1860×2480、300 DPI 的屏幕参数生成真实页面。阅读区显示原生帧缓冲输出，支持翻页、点左右区域翻页和目录跳转。它不经过浏览器重新排版；浏览器近似模式仍可在设置中明确选择。

原生预览翻页时保留当前页面，下一页图像解码就绪后才切换，不再用整屏加载提示遮住正文。Aa 提供纸张翻页、轻柔切换、即时切换；默认纸张翻页，遵循系统减少动态效果设置。左右方向键、点击页面左右区域或横向滑动均可翻页，输入文字与隐藏的阅读区不会响应翻页按键。第一页、末页与正在翻页时会限制重复请求。动效只作用于 KOReader 已生成的页面图像，字体、换行、分页及原始书籍保持不变。

应用启动时就在后台准备 KOReader，即使书库为空也会启动常驻进程。首次打开书籍、换书和 Aa 重新加载设备排版复用同一进程，并为每次文档加载准备独立的原件副本与设备侧录；异常退出时恢复进程和阅读位置。切换书库、找书和个人页面保留阅读器会话、页码与搜索结果，离开页面不关闭后台引擎。临时原件、侧录及截图位于当前用户临时目录的 `KindleSpouse-reader`，按应用资料目录隔离，并将访问权限限制到当前 Windows 用户和系统，供 WSL 读取。临时副本未加密，原始资料的 EFS 加密设置保持不变。旧页面图像及时清理，退出应用时释放进程与临时副本。隐藏的浏览器试读不响应其他页面的翻页按键，电脑试读不计入 Kindle 阅读统计。

通过网盘同步的书籍侧录按文件身份及内容指纹匹配，读取字体、字号、页边距、行距、内嵌样式和渲染版本等设置。Lua 仅解析为数据，不执行侧录代码。已取得该书设置时显示已匹配；新书沿用最近一次匹配的设备排版，并明确标注尚未单独核对。没有设备配置时使用 KOReader 默认设置并提示。缺少指定字体会停止一致预览，不静默换字体。

“同版引擎”不等于已经完成所有书籍的逐页比对。设备上的字号、字体、页边距、方向或样式更新后，需要保存退出书籍、同步网盘，再在 Aa 中重新加载设备排版。电脑预览内保持设备版式只读；它不会把桌面 CSS 设置写成设备配置。灰阶显示、屏幕物理尺寸和电子墨水刷新不能由电脑显示器复现。

Windows 运行原生预览需要已可启动的 WSL Ubuntu。开发时运行 `npm run tools:reader` 安装经过固定 SHA-256 校验的官方组件，安装包只携带解压后的独立运行时及许可证。临时原件和 PNG 放在当前用户临时目录下受限访问的 `KindleSpouse-reader`，退出应用后清理；该目录不会进入源码或安装包，长期个人数据仍在用户数据目录。

桌面预览关闭模拟器的自动休眠与自动关机，避免闲置后屏保拦截翻页。心跳临时读空时保留最近有效记录，使用阅读器本机时间计算失联期限；真正失联的进程仍会退出。进程中断后，下次翻页会尝试从最后确认的位置恢复一次；失败时显示清楚的提示及“重新打开”按钮。诊断日志仅保存在本机用户数据目录，不上传账号、书籍或阅读内容。

## 无线连接如何工作

网盘是文件交换仓库，Kindle 上的独立配套进程负责领取书籍和上传笔记。电脑和 Kindle 不需要位于同一局域网，电脑在上传完成后可以关闭。

电脑端“下载”只发布已确认的书籍。新版 Kindle 插件默认启用 Automatically receive books：KOReader 打开或唤醒后约 8 秒检查，运行期间每 90 秒在 Wi-Fi 已连接时后台检查新书，不自动打开 Wi-Fi；不运行 KOReader、离线或休眠时等待下次机会。独立 books-only 流程校验配对、接收文件、验证内容并上传回执，不采集或上传标题、笔记及整库快照。原有笔记备份暂停状态保留；Pause sync 同时暂停自动取书，重新启用自动取书或 Resume sync 可恢复。首次需要更新一次三个设备组件，之后日常通过网盘完成。

Kindle 端 Sync now 继续负责完整双向同步。电脑端“从网盘更新笔记”及“读取笔记与回执”读取设备已上传的内容，不会远程启动 Kindle 同步，也不代表书籍已经下载到设备。

书籍：下载／导入 → KOReader 原件试读 → 明确确认 → 上传并回读校验 → 发布领取清单 → Kindle 下载并回读校验 → 返回设备回执。

笔记：Kindle 配套进程制作只读稳定快照 → 按内容指纹上传原始笔记、书籍侧录、目录及 KOReader 统计 → 桌面点击网盘同步 → 校验清单和原件 → 分类、关联标题并更新预览。

默认同步范围不包含整台设备的书籍原件。接收的书已经保存在网盘；设备上传笔记和阅读资料。没有上传完成清单的半成品不会取代上次成功快照。冲突原件以不同指纹保留，应用不覆盖原生笔记，也不把电脑上的 PDF 改写回 Scribe 手写数据。

“已上传”表示网盘文件完成回读校验；“设备已校验”需要真实设备回执。OPDS 仍作为可选局域网方式，只有这个方式需要电脑保持运行。

## 首次配对

1. 在“我的网盘”连接 Google Drive 或 OneDrive，由本人完成服务商授权。
2. 点击“配对 Kindle”，在新打开的页面完成设备专用的单独授权。应用通过交换目录标记核对两次授权是否指向同一个网盘，随后自动将私有安装包保存到“文档”并打开所在文件夹；已有同名安装包时使用新文件名保留原件。授权可等待 30 分钟，退出应用会取消未完成的授权。过期页面不能靠刷新恢复，需要重新点击配对并使用最新页面。
3. 保存并退出 KOReader，将安装包解压到已越狱 Kindle 的 USB 根目录。只需首次安装使用 USB；包内包含 `kindlespouse`、KOReader 插件和可选 KUAL 入口。
4. 拔线、连接 Wi-Fi，打开 KOReader → KindleSpouse → Sync now，或 KUAL → KindleSpouse → Sync now。同步在后台进行，KOReader 只在手动启动和结束时显示短暂提示，不拦截翻页。打开 Sync status 可查看阶段、文件数和耗时，点屏幕即可继续阅读；Last result 同样可以查看状态。上次完成的结果会保留到下一次同步结束，重复点击不会启动第二个任务。

Scribe 的笔记标题读取专用 `ksdk.content.db` 中的 `Nodes` 索引，并以完整 UUID 匹配笔记；手动修改的标题会保留。标题索引会优先通过网盘同步，完整笔记备份尚未完成时，桌面“刷新标题”也可以单独读取。设备端的 Sync titles 只传标题索引，不依赖 USB；Collect notebook titles 保留为离线诊断入口。笔记页会显示已匹配标题的数量。

变化的小文件以 16 MiB 原始内容为目标组成压缩包，单个较大原件独立成包；设备复用网盘连接并发上传两个包，桌面最多并发下载四个包。旧版已上传的散文件可继续复用。暂停后已经完成的包会保留，继续时只上传缺少的内容。桌面按内容指纹缓存原件并复用已有备份；重复同步不会重新下载未变化的原件。每个包及解压后的原件都经过 SHA-256 校验，完整清单只在传输成功后发布。设备同步以较低优先级运行，进度只在手动打开 Sync status 时刷新，可查看传输包数、数据量和速度，不影响继续阅读。

设备端 Pause sync 会停止当前传输并保留已经上传的文件，Resume sync 继续时会跳过相同内容。暂停期间关闭书籍不会自动恢复完整备份；仍可使用 Sync titles 单独更新标题。
5. 桌面“我的网盘 → 读取笔记与回执”读取笔记、统计和设备回执，也可在“笔记与标注 → 从网盘更新笔记”读取。KOReader 关闭书籍时也会在已有网络下尝试启动独立同步进程。

设备组件面向 Scribe 使用的 Linux ARMv7。它不会升级固件、唤醒休眠设备或自动打开 Wi-Fi。读取活跃的内容目录及统计数据库需要设备上可用的 `sqlite3 -readonly`；不满足时保留已有快照并报告错误。原生手写笔记保存后在下一次手动同步中采集，不承诺拦截原生保存事件。

私有安装包含设备专用网盘授权，不能放入源码仓库或公开分享。桌面可撤销应用配对；丢失设备时还应在 Google／Microsoft 账号中撤销相关授权。

## 笔记与数据迁移

v0.3 首次启动先备份原数据库，再从已有设备快照重建书库，重新分类历史笔记记录。原始书籍、笔记及附属文件不会删除。导入文件数量与可阅读笔记本数量分别统计，不把没有页面的容器计作笔记本。

没有设备目录时显示“未识别标题”，不会以猜测名称代替真实标题。配套进程上传目录后按身份匹配；也可以手动命名。模板底纹及所有特殊笔刷尚不能完全还原；不能解析的格式保留原件。

本机数据位于当前用户 `%APPDATA%/KindleSpouse`。桌面凭据通过 Electron safeStorage 加密，外部工具配置按操作临时生成。源码不包含书籍、笔记、设备标识、授权、数据库、安装配对包、日志或个人截图。复制源码不等于备份个人资料。

## 开发与检查

Windows 10/11、Node.js 24。Calibre 是可选外部程序，在设置中选择包含 `calibre-debug.exe`、`calibredb.exe` 和 `ebook-convert.exe` 的目录；应用使用独立书库。

```sh
npm ci
node node_modules/electron/install.js
npm run tools:install
npm run tools:reader
npm run tools:companion
npm run dev
```

```sh
npm run build
npm test
npm run check:comments
npm run test:e2e
npm run test:douban
npm run test:companion
npm run test:reader
npm run check:formats
npm run test:formats
npm run test:formats-ui
npm run test:companion-formats
npm run check:publication
npm run package
```

`test:e2e` 使用应用自己生成的使用指南，启动真实 Electron，验证下载、EPUB/PDF、收藏与确认、OPDS、标注正文定位、笔记导出、布局和资料菜单。它使用隔离用户目录，不是私人书库。

`test:companion` 运行真实独立同步进程及 rclone，以隔离的本地网盘适配器验证文件领取、指纹、快照、回执、重复同步、路径限制和撤销配对。该测试不代表真实 Google Drive／OneDrive 账号或物理 Kindle 验证通过。真实授权和设备首次启动需本人完成。

`test:reader` 需要 Windows、WSL Ubuntu 和固定版本的 KOReader 运行组件，以应用生成的单文件长章节实际验证原生分页、第二页 PNG、原件不变、确认前无传输，以及拒绝引擎错误页面。普通 `npm test` 不要求 Linux 运行环境。

`test:reader-startup` 启动真实 Electron，先在空书库验证原生引擎已准备，再导入书籍、核对复用启动时的运行目录和页面切换会话，最后验证退出应用会清理进程及临时文件。Lua 文档切换与路径限制测试同时在 CI 运行。

`check:formats` 验证桌面注册表与设备格式列表一致。`test:formats` 使用 Calibre 为验收生成不同格式的原件，再由真实 KOReader 验证打开、翻页、续读、强制重载与原件不变，涵盖 EPUB、MOBI、FB2、DOCX、TXT、RTF、HTMLZ、FB2.ZIP、TXT.ZIP、HTML、Markdown、PDF、PNG 和 CBZ。设置 `KINDLESPOUSE_CALIBRE_DIRECTORY` 为包含 `ebook-convert.exe` 的目录；可选 `KINDLESPOUSE_FORMAT_BOOK` 指定自有验收 EPUB。测试转换仅用于生成样本，不属于应用试读路径。

`test:formats-ui` 启动真实 Electron，验证 MOBI 自动使用原生引擎、导航保留会话、被其他阅读器替换后恢复页码及 Aa 重新加载。`test:companion-formats` 使用隔离 rclone 网盘适配器验证 MOBI、FB2.ZIP、TXT 原件领取、能力回执和去重；它不代表物理 Kindle 或真实 Google Drive 已完成新格式验证。

`test:cloud` 使用 502 个生成文件验证压缩包上传、桌面批量读取、标注增量更新、独立标题索引和缓存复用；需要先构建设备组件及本机验收程序。可在参数中传入旧版本本机验收程序路径，比较同一组文件的完整同步耗时；本地适配器结果不代表真实网盘的网络速度。

`test:local-profile` 使用真实 HTTPS 服务、设备同步程序和隔离 rclone 目录，验证照片与设置直连、即时回执、证书固定、凭证拒绝、撤销配对、旧网盘回执保护，以及直连不可用时的网盘回退。直连成功的验收将网盘程序指向不存在的文件，确保该流程没有调用网盘。运行前需构建设备组件；CI 同时运行 Go 端的证书与传输测试。这些结果不代表物理 Kindle 的无线速度。

休眠封面与标注写回使用

- 开发构建先运行 `npm run tools:kfx`、`npm run tools:sleep-cover` 和 `npm run tools:companion`。`npm run package:device` 生成不含授权信息的设备更新包。
- 首次更新需退出 KOReader 并连接 USB，再运行 `scripts/install-device-update.ps1`。安装器逐文件回读校验，保留旧组件备份及现有网盘授权、暂停状态；新同步二进制暂存为 `kindlespouse-sync-next`，下次启动同步时激活。安装器不修改书籍和笔记目录。
- 退出 USB 后重启 KOReader，在 KindleSpouse 菜单启用 `Use KindleSpouse sleep cover`。休眠页包括当前书籍封面、标题、作者、进度、个人头像文字、今日阅读分钟数和连续阅读天数，标签使用英文。缺少封面时生成文字书封；长标题会缩小并限制高度。设备离线读取 KOReader 自己的统计，不使用电脑应用在线时长。
- 电脑「设置与设备 → Kindle 休眠封面」可以选择书籍生成真实 KOReader 预览，并上传封面偏好；Kindle 下次同步会收到。电脑预览采用最近同步的设备统计，不能代表尚未上传的阅读记录。启用和关闭封面会保留并恢复之前的休眠方式。
- 标注页面按书籍版本显示左侧书目、中间标注和右侧常显阅读器。原生模式用真实 KOReader 搜索引文；重复、缺失、仅跳到来源页分别提示。完整无加密 PDOC KFX 可以生成独立 EPUB 或嵌入 PDF 阅读副本，原件保留。
- 修改 KOReader 标注后，电脑自动发布待处理任务；Kindle 自动同步时下载任务。为避免覆盖正在阅读的内存状态，插件只在退出书籍后应用待办，保留原始 sidecar 备份；随后自动上传回执，电脑收到回执才显示设备已应用。也可在文件浏览器选择 Apply pending annotation edits。版本冲突会保留双方内容。
- Kindle 原生标注仅提供本机编辑整理和可撤销归档，不宣称写回 Kindle 原生阅读器。JSON 导出保留源记录和编辑状态，Markdown 导出使用当前有效笔记并跳过归档。
- 实机安装、实际休眠截图和 Google Drive 上的设备编辑回执需要在用户设备完成验收。源码和 CI 不包含书籍、私有图片、笔记、数据库、授权或配对包。

头像与封面局域网同步

- 在「设置与设备 → 头像与封面直连」启用直连，选择已配对的 Kindle 保存私有连接包。首次更新需退出 KOReader 并通过 USB 安装，运行 `scripts/install-local-profile.ps1 -Package <连接包路径>`；安装器核对设备身份并逐文件回读，保留现有网盘授权、暂停状态及正在使用的同步程序。此包含设备凭证，不能上传 GitHub 或分享。
- 电脑保持 KindleSpouse 运行，Kindle 与电脑连接同一网络。在 KindleSpouse 菜单选择 `Sync profile now`，只接收照片头像、昵称及休眠封面开关，不读取书籍、笔记或标题索引；完整备份暂停时也可以单独运行。照片确认后电脑立即显示设备回执，Kindle 后台刷新休眠封面缓存，日常无需 USB。
- 直连使用 HTTPS、电脑证书固定及每台设备独立凭证，默认监听端口 41943，不接受网页跨域访问。电脑保存资料后可立即直连接收；网盘备用副本仍在后台发布。直连尝试总计最多 6 秒，无法连接时自动回退网盘。学校／公司网络的设备隔离或防火墙可能阻止直连，此时可继续使用原有网盘路径。
- 当前连接包绑定电脑的局域网地址与身份；更换网络或地址后需要重新导出连接配置。电脑关闭、禁用直连或设备离开同一网络时使用网盘。书籍、笔记和标注仍走原有网盘流程。

网盘自动同步

- KindleSpouse 菜单默认启用 `Automatically receive books` 和 `Automatically sync notes and reading history`。KOReader 运行且 Wi-Fi 已连接时，新书约每 90 秒检查一次。完整同步由变化触发：启动文件浏览器检查一次笔记，关书或修改标注后安排更新，持续翻页的阅读进度与 KOReader 记录约每 10 分钟合并上传；自动完整同步之间至少间隔 1 分钟。上传前调用 KOReader 自己的保存流程，增量对象复用原有校验和缓存，不重新上传未变化的笔记内容。
- 空闲且没有变化时不会运行完整备份，每 10 分钟只接收资料与待处理标注修改，跳过标题数据库备份、笔记扫描、书籍领取和快照上传。已经关闭的书籍才会应用电脑编辑，应用结果会触发下一次增量同步。
- 电脑的「设置与设备 → 默认网盘 → 自动更新笔记、标注与阅读记录」默认打开。应用启动后和运行期间自动读取已配对设备的更新并发送待处理标注修改，通常每分钟检查一次。检查已导入的快照时只读取小型状态文件和索引，手动「立即更新」仍会验证并修复本机快照。
- 自动任务在后台运行，不弹出完成提示，也不主动开启 Wi-Fi；休眠时停止安排新任务，唤醒或恢复网络后继续检查。网络失败逐步降低重试频率，最长约 15 分钟；支持多个已配对网盘账号，单个账号失败不阻塞其他账号。
- `Pause sync` 保留现有暂停语义，不会被定时器自动解除。需要恢复时选择一次 `Resume sync`；也可以关闭对应自动同步开关。退出 KOReader、系统休眠或 Wi-Fi 关闭期间无法执行新的网盘同步；电脑关闭时 Kindle 仍可上传到网盘，电脑下次启动再读取。
- 现有设备需退出 KOReader 后通过 USB 安装一次新版组件。运行 `node scripts/build-auto-receive-update.mjs --full-sync` 生成不含授权信息的 `artifacts/KindleSpouse-AutoSync-Update.zip`，再运行 `scripts/install-auto-receive.ps1 -Package artifacts/KindleSpouse-AutoSync-Update.zip`。安装器只更新并回读校验三个组件，保留现有授权、书籍和暂停状态。日常自动同步无需 USB。

Kindle 专用书籍目录

- 默认目录为 `KindleSpouse/Inbox`，可在「设置与设备 → 默认网盘 → Kindle 书籍目录」修改。应用自动创建目录并发布经过回读验证的目录配置。笔记、授权状态和传输回执放在独立的 `KindleSpouse/Sync`；书籍目录不能覆盖该目录或其父目录。
- 应用中确认下载的书会上传到该目录。也可直接用 Google Drive 或 OneDrive 放入 EPUB、PDF、MOBI 等 KOReader 支持的书籍，Kindle 在自动收书时发现并补收，无需为每本书在电脑创建传书任务；电脑关闭后仍能收取已经放入网盘的文件。支持最多 8 层子目录，跳过隐藏目录、`.sdr` 附属文件和不支持的格式，单个文件限制 200 MB。
- 去重使用文件内容：优先比较网盘提供的校验值和设备已验证的本机索引，文件名不同也能识别；无法预先比较时下载到暂存区计算指纹。新增文件写入 `Books/Inbox` 并回读验证，稳定的文件和已完成的传书任务复用缓存，不反复下载书籍或逐一读取旧任务正文。
- 设备缺少的书会补收，云端内容改变会保留新的独立版本；网盘移走文件不会删除 Kindle 文件，也不会覆盖已有不同内容的设备文件。目录与逐书回执分开保存，应用传书仍以对应任务的内容指纹回执为准。
